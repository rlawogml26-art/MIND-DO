# 코드 리뷰 기준

이 레포의 코드는 대부분 AI가 작성한다. 리뷰는 한국어로, 쉬운 말로 작성한다.
코드 모양, lint, 타입 오류는 CI가 이미 검사하므로 지적하지 않는다.

## 🔴 반드시 지적 (보안)

- 열람 권한: 티켓·사진 등 다른 사용자의 데이터에 접근하는데 티켓 service의 열람 권한 함수를 거치지 않음. 수정·삭제에서 주인 확인이 없음. "로그인 여부"만 확인하고 끝냄. 열람 판단 함수가 티켓 service 밖에 새로 생기거나 여러 벌로 나뉨
  - 열람 기준: 공동 티켓과 그 안의 개인 티켓은 그 그룹에 속한(나가지 않은) 멤버만, 개인 보관함은 본인만. 친구공개·전체공개·팔로우 같은 공개 범위 로직이 생기면 지적 (SNS 기능은 폐지)
  - 수정·삭제: 개인 티켓 수정·원본 삭제는 주인만, 공동 티켓 제목 수정과 초대자 추가·제외는 공동 티켓 생성자와 그룹장만. 공동 티켓을 삭제하는 코드가 생기면 지적
  - 볼 권한이 없는 티켓에 403을 응답함 (404여야 함. 403은 볼 수 있는 티켓을 주인이 아닌 사람이 수정·삭제할 때만)
  - 다른 멤버의 미완성 개인 티켓 응답에 사진·메모가 들어감 (빈 슬롯 상태만)
  - 그룹장이 **현재 멤버**의 티켓 연결을 끊을 수 있음 (그룹장은 강퇴할 때 남기기·일괄 제거 중 선택, 이미 나간 사람의 기록만 나중에 일괄·하나씩 제거 가능)
  - 강퇴된 사람에게 자기 티켓의 그룹 연결 여부가 응답에 드러남
- 본인 판단: 요청한 사람을 body·쿼리·경로의 userId로 판단함. 로그인이 붙기 전에는 서버가 고정한 테스트 사용자, 붙은 뒤에는 쿠키의 JWT에서 꺼내야 함. (그룹·공동 티켓·다른 멤버처럼 대상을 가리키는 id는 괜찮음. 단, 요청한 사람은 위 방식으로 꺼내 그룹 소속·권한을 확인해야 함)
- 테스트 사용자: 요청자를 꺼내는 코드가 한 곳이 아니라 여러 곳에 흩어져 있음 (로그인이 붙을 때 한 곳만 바꿔야 함)
- 소프트 삭제: 티켓 조회(단건·목록·검색)에 deleted_at이 비어 있는 조건이 빠짐. 삭제 API가 줄을 지우지 않고 deleted_at만 기록하는지
- 토큰: 로그인 토큰을 응답 body에 넣음. 앱이 토큰을 직접 읽거나 저장함(AsyncStorage, SecureStore 포함). 토큰 갱신(POST /api/auth/refresh)이 쿠키가 아니라 body에서 리프레시 토큰을 읽음. 쿠키의 httpOnly를 끔. dev·운영에서 Secure를 끔(끌 수 있는 건 로컬뿐). 쿠키에 Domain을 지정함. trust proxy를 true로 둠 (1이어야 함)
  - 리프레시 토큰: DB에 원본을 저장함(SHA-256 해시만). 갱신할 때 새 토큰을 발급하지 않거나 이전 토큰을 무효로 만들지 않음(로테이션). 무효가 된 토큰이 다시 들어왔을 때 그 사용자의 토큰을 모두 무효로 만들지 않음. 로그아웃 때 서버에서 무효화하지 않고 쿠키만 지움
  - 앱이 토큰 갱신 요청을 동시에 여러 번 보낼 수 있음 (공통 서버 호출 코드 한 곳에서 하나만 보내야 함)
  - 초대 링크 토큰: DB에 원본을 저장함(SHA-256 해시만). 원본 토큰을 로그에 남기거나 조회 API로 다시 돌려줌
- 사진: 고정 주소로 응답함(열람 권한 검사를 통과한 경우에만 S3 Presigned URL 발급). 만료 시간을 코드에 숫자로 씀(환경변수여야 함). 파일 이름이 순서 번호나 사용자 ID임(UUID여야 함). 앱이 사진 링크를 저장함. S3 객체를 공개(public-read)로 올림. 사진 링크를 만드는 코드가 서버의 한 함수가 아니라 여러 곳에 있음. DB에 S3 key가 아니라 URL을 저장함
- 비밀값: 키·비밀번호·토큰이 코드, 로그, frontend/, shared/, EXPO_PUBLIC_ 변수, .npmrc에 들어감. .env 파일이 커밋됨. AWS SDK에 accessKeyId·secretAccessKey를 직접 넘김 (서버는 IAM Role 사용)
- 입력 검증: 요청 body·쿼리·경로 파라미터를 zod 검증 없이 사용함
- AI 초안: AI 출력을 zod 검증 없이 저장·응답함(형식, 카탈로그 ID, shared/ 태그 목록 안의 값인지). 분위기 프롬프트를 지시 자리에 넣거나 그 내용으로 규칙을 바꿈(구분된 자료 칸에). 분위기 프롬프트 원문을 로그·DB에 남김. 분위기 프롬프트와 개인 티켓 뒷면 메모를 같은 필드·같은 검증(500자)으로 처리함. Bedrock을 액세스 키로 호출함(IAM Role). 모델 ID·리전·타임아웃을 코드에 직접 쓰거나 타임아웃에 기본값을 둠(AI_TIMEOUT_MS가 없으면 서버 시작 때 에러). AWS SDK 자동 재시도를 끄지 않음. 실패 시 1회 재시도 후 기본 템플릿을 주지 않음. AI가 사진을 바꾸거나 새로 그림. 초안 3개를 DB나 서버 메모리에 저장함(횟수만 DB에 기록). 사용자가 고른 디자인을 저장할 때 카탈로그 기준으로 다시 검증하지 않음
- 비밀번호: 해시 없이 저장함. 응답에 해시값이 포함됨. 비밀번호·토큰·개인정보를 로그에 남김. 요청 body를 통째로 로그에 찍음
- 에러 응답: 500 응답에 스택, SQL, 파일 경로 등 내부 정보가 들어감 (응답은 일반 문구, 상세는 서버 로그에만)
- 서버 디스크나 메모리에 파일·세션·상태를 저장함 (서버는 언제든 교체·추가됨)
- DB TLS: 인증서 검증을 끔(rejectUnauthorized: false 등). DB_SSL_CA_PATH 대신 환경 이름으로 TLS 여부를 정함
- 규칙 우회: any, eslint-disable, @ts-ignore, @ts-expect-error, as로 타입 에러 덮기. tsconfig의 strict를 끄거나 ESLint 규칙을 off로 바꿈

## 🟠 구조 위반

- 티켓 입력 규칙 위반 (AGENTS.md 티켓 입력 규칙 기준. 1차 시연 규칙 title·location·visitDate·memo, 15자·80자는 더 이상 기준이 아님)
  - 공동 티켓: 날짜 필수·생성 후 수정 불가, 제목 선택·최대 12자, 미래 날짜 불가, 같은 그룹·같은 날짜에 1개. 장소 칸이 생기면 지적 (11/4 장소 삭제)
  - 초대자: 공동 티켓 생성자가 그룹 멤버 중 골라 초대하고, 추가·제외는 생성자와 그룹장만. 다른 멤버가 초대자를 바꿀 수 있으면 지적. 그룹 전원을 자동으로 초대자로 만들거나, 초대자가 아닌 사람에게 슬롯이 생기면 지적
  - 개인 티켓: 사진 1~4장 필수, 뒷면 메모 선택·최대 500자, 한 공동 티켓에 한 사람당 1장. 개인 티켓에 장소 칸이 생기면 지적
  - 공동 티켓 없이 개인 티켓을 만드는 경로가 생김 (혼자 만드는 티켓은 없음. 개인 티켓은 공동 티켓의 자기 슬롯에서만 생성)
  - 개인 티켓 원본 삭제와 그룹 연결 제거를 같은 코드로 처리함 (원본 삭제는 보관함·그룹 양쪽에서, 연결 제거는 그룹에서만)
  - 꾸미기 결과(프레임·스티커·텍스트 배치)를 서버에 저장하지 않음
  - 마이페이지 닉네임·소개는 15자(shared의 PROFILE_NICKNAME_MAX·PROFILE_BIO_MAX)
  - 날짜가 YYYY-MM-DD 문자열이 아니거나, DB에 날짜 전용 타입이 아닌 형태로 저장함. repository가 Prisma의 Date 객체를 문자열로 바꾸지 않고 반환함 (응답 스키마 parse에서 500이 남)
  - 영문 필드 이름을 ERD(schema.prisma)와 다르게 새로 지음
  - 보관 기간·만료, 개수 제한처럼 기획에 없는 동작을 추가함
  - 제한 숫자나 검증 스키마를 shared/가 아닌 곳에 따로 만듦. shared/ 안에서도 같은 규칙의 상수·스키마를 이름만 바꿔 또 만듦 (예: 비밀번호 길이 상수가 두 벌)
  - 수정 일시(updatedAt 등)를 API 응답에 넣음 (내부 데이터로만 씀)
- 그룹 규칙 위반 (AGENTS.md 그룹 규칙 기준)
  - 그룹 인원 1~6명이 아님(7번째 가입을 막지 않음). 그룹명이 최대 8자가 아님
  - 한 사람이 기본 1인 그룹을 빼고 그룹 5개 이상에 속할 수 있음 (최대 4개)
  - VIP 재생성을 사용자 단위로만 셈 (사용자·그룹 단위로 그룹마다 하루 3회, 기본 1인 그룹 포함)
  - 기본 1인 그룹: 가입 시 만들어지지 않음, 기본 1인 그룹에 초대 링크를 발급하거나 가입시킴, 나가기·삭제를 허용함, 참여 그룹 상한(4개)에 포함해서 셈
  - 초대 링크: 그룹 멤버가 아니어도 만들 수 있음, 그룹장만 만들 수 있게 막음, 새 링크를 만들 때 다른 링크를 무효로 만듦, 1회용으로 만듦, 유효 기간을 코드에 숫자로 씀 (24시간, 환경변수)
  - 나중에 들어온 멤버에게 그룹장·공동 티켓 생성자 권한이 자동으로 넘어감 (그룹장이 나갈 때 가입 순서로 자동 승계하는 것은 정상). 그룹장이 모든 공동 티켓의 제목 수정·초대자 관리를 할 수 있는 것은 정상 (11/4 결정)
  - 홈 달력 미리보기에 다른 멤버의 티켓이 들어감 (내 티켓만)
  - 강퇴된 사람의 재참여(초대 링크로 다시 들어오기)를 막음
  - 그룹의 모든 초대 링크를 한꺼번에 무효로 만드는 기능을 그룹장이 아닌 사람도 쓸 수 있음
- AGENTS.md 임시값(토큰 1시간·30일, 비밀번호 8~64자, 사진 JPEG·PNG 장당 10MB(HEIC는 앱이 JPEG로 바꿔 올림), 가입 즉시 로그인, 분위기 프롬프트 50자, 초대 링크 24시간)과 다른 값을 씀. 숫자를 코드에 직접 씀(환경변수나 shared/에서 읽어야 함)
- 백엔드 호출 방향(요청 처리 → service → repository) 위반, repository 밖의 Prisma 호출, 다른 기능의 repository나 테이블을 직접 조회함
- 기능 코드가 backend/src/modules/기능명/ 밖에 생김. DB 스키마가 backend/prisma/ 밖에 생김

## 후속으로 넘긴 항목

- 해당 코드 위치의 주석 또는 PR 본문에 "후속 Issue #번호"와 함께 미구현을 밝힌 항목은 🔴·🟠 개수에 넣지 않고, 요약 아래 "후속 확인" 칸에 한 줄로만 적는다
- PR 본문을 볼 수 없으면 코드 주석만 기준으로 판단하고, 요약에 "PR 본문 미확인"이라고 적는다
- Issue 번호 없이 "나중에 구현", "사용자가 허용함", "임시" 등으로만 적힌 항목은 원래 심각도대로 지적한다

## 지적하지 않는 것

- 코드 모양, 이름 취향, 사소한 성능 최적화
- 미확정 사항에 대한 설계 제안 (AGENTS.md 미확정 사항 기준): 사진 업로드 방식, AI 초안의 스티커 배치 주체, 태그 목록·추천 칩, AI 사용 방식 전반 재검토, 공동 티켓 날짜 시간대·동시 생성 처리(D04), 그룹명 변경 시 기존 공동 티켓의 그룹명 표시(D02), 혼자 남은 그룹이 삭제될 때 개인 티켓 원본 처리, 로컬 개발용 DB, 테스트 방식, 서버 로그 방식, EAS 사용 여부
- 임시값 자체를 바꾸자는 제안 (값은 확정 시 바뀜)

## 작성 방식

- 심각도는 🔴를 critical, 🟠를 major, 🟡를 minor로 매긴다
- 첫 요약에 🔴·🟠·🟡 개수와, 팀장이 직접 볼 곳을 파일명과 함께 3개 이내로 적는다
- 🔴·🟠는 병합 전 필수 수정, 🟡는 작성자 판단이라고 요약에 함께 적는다
- 각 지적은 무엇이 문제인지, 왜 위험한지, 어떻게 고치는지를 한두 문장으로 쓴다
- 위반이 없으면 "보안·구조 기준 위반 없음"이라고만 쓴다
